# 10 · 迁移 / 备份 / 恢复

---

## 1. 需要备份的三类东西

| 类别 | 存在哪 | 是否已随仓库备份 | 丢失后果 | 备份方式 |
|---|---|---|---|---|
| **代码 / 数据 / 文档** | GitHub 仓库 | ✅ 天然备份 | 无（可 clone 回来） | 无需额外备份 |
| **GitHub token** | 本机 `tools/.gh_token` | ❌ **故意不入库** | 无法推送（但数据不丢） | 存密码管理器 |
| **浏览器端计划进度** | 访客浏览器 localStorage | ❌ **不可能入库** | 弟弟的完成进度丢失 | 页面「导出」按钮 |

> 结论：**仓库里没有的东西只有 token 和终端用户的勾选进度**。前者重签即可，后者需手动导出。

## 2. 备份操作

### 2.1 仓库备份（通常不需要）

远端 GitHub 本身就是备份。若要额外留一份离线副本：

```bash
cd /d
git clone --mirror https://github.com/zhuxingshifu1992/hefei-job-help.git hefei-job-help-mirror.git
# 生成一个完整镜像（含所有分支/tag），拷到移动硬盘即可
```

或打包含工作区的完整快照：

```bash
cd /d/帮老弟找工作项目
tar -czf "hefei-job-help-$(date +%F).tar.gz" \
  --exclude=.git --exclude=.workbuddy --exclude=tools/.gh_token .
```

### 2.2 Token 备份

```bash
# 查看（不要打印到聊天窗口/日志里）
wc -c tools/.gh_token
```

**正确做法**：把 token 值存进密码管理器（如 1Password / Bitwarden），条目备注写清用途与过期时间。
**禁止**：截图、写在 md 里、发聊天、提交进仓库。

### 2.3 浏览器端计划进度备份（给终端使用者）

在 `plan.html`（或任意页面）点右上角 **「导出」**，会自动下载：

```
jobsearch-backup-YYYY-MM-DD.json
```

内容形如：
```json
{ "wb_jobsearch_plans": "[...]", "wb_jobsearch_fav": "...", "wb_jobsearch_joined": "..." }
```

**什么时候需要导出**：
- 换手机 / 换浏览器前
- 清理浏览器数据前
- 计划重置前（想保留旧进度时）

恢复：点 **「导入」** 选这个文件。

## 3. 换机迁移步骤（新电脑 / 新 agent）

```
1) 装 Git，配身份
   git config --global user.name  "名字"
   git config --global user.email "邮箱"

2) 克隆仓库
   git clone https://github.com/zhuxingshifu1992/hefei-job-help.git "D:/帮老弟找工作项目"
   cd /d/帮老弟找工作项目
   git config core.autocrlf input

3) 放 token
   printf '%s' '你的token' > tools/.gh_token
   git check-ignore -q tools/.gh_token && echo "OK 已忽略" || echo "⚠️ 检查 .gitignore"

4) 核对环境路径（最容易出错的一步）
   bash delivery/06-配置模板与脚本/health-check.sh
   若 Python/Node 路径失效：
     ls -d "C:/Users/YC1039/.workbuddy/binaries/python/versions/"*/
     ls -d "C:/Users/YC1039/.workbuddy/binaries/node/versions/"*/
   把 delivery/ 与 tools/ 脚本里的旧路径改成实际路径

5) 跑一次完整闭环验证
   bash delivery/06-配置模板与脚本/daily-update.sh --force

6) 重建自动化（.workbuddy/ 不入库，必须手动建）
   参数见 04-日常更新与运维节奏.md §1.1

7) 读历史上下文
   memory/decisionLog.md  → 历史决定
   memory/.handoff.md     → 最新交接状态
```

## 4. 灾难恢复

### 场景 A：本地目录整个没了

```bash
git clone https://github.com/zhuxingshifu1992/hefei-job-help.git "D:/帮老弟找工作项目"
cd /d/帮老弟找工作项目
printf '%s' 'token' > tools/.gh_token
```
**数据一条不丢**——所有资讯、计划、文档都在仓库里。

### 场景 B：误提交/误改，想回到某个版本

```bash
git log --oneline -10                 # 找目标
git revert <commit>                   # 生成反向提交（推荐，安全）
# 或只恢复单个文件
git checkout <commit> -- data/_source.json
```

### 场景 C：`info.json` 被手改坏了

```bash
node tools/gen-info.js                # 从 _source.json 重新生成即可
```
> `_source.json` 才是权威源，`info.json` 随时可重建。

### 场景 D：token 泄露

1. GitHub → Settings → Developer settings → **Revoke**（立刻）
2. 重新签发新 token，写入 `tools/.gh_token`
3. 检查仓库历史是否含 token：`git grep -nIE "github_pat_" -- .`
4. 若含，需清洗历史（超出本交付包范围，建议直接重建仓库并 force push）

### 场景 E：GitHub 仓库被删

- 若有 `--mirror` 镜像：重新建空仓库后 `git push --mirror`
- 若无镜像：联系 GitHub Support（有 30 天恢复窗口）；同时本地工作区若还在，可重新建仓推送

### 场景 F：腾讯文档表格丢失

- **不影响发布**：`data/_source.json` 是权威源，重新生成即可
- 重建表格：用 `tools/seed_tdoc.py`（一次性播种脚本）把现有 `info.json` 推回新表格
- 建表后更新 `fetch_tdoc.py` / `sync_tdoc.py` 里的 `FILE_ID` / `SHEET_ID`

## 6. 交接给下一位维护者时，给他的三句话

1. **数据权威源是 `data/_source.json`**，腾讯文档只是镜像；`info.json` 由脚本生成，别手改。
2. **推 `main` 等于发布**，Pages 40~60 秒生效；推送常需重试 2~3 次，属正常。
3. **出问题先读 `delivery/08-故障排查手册.md`**，九类真实故障都在里面，别急着重新授权或重建仓库。
