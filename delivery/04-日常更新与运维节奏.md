## 1. 三种运维节奏

| 节奏 | 频率 | 做什么 | 当前状态 | 谁触发 |
|---|---|---|---|---|
| **每日资讯同步** | 每天 | 拉腾讯文档 → 生成 → 推送 | **已 PAUSED** | 自动化 `automation-1785898412205` |
| **每两周主动巡检** | 每两周日 | 联网搜新平台 → 筛选 → 加数据 → 同步 → 推送 | **ACTIVE** | 自动化 `automation-1785980498191` |

## 2. 核心流程：一次完整更新（照抄顺序执行）

### 2.1 数据同步型（每日/按需）

```bash
cd /d/帮老弟找工作项目

# ① 拉取腾讯文档最新表格 → data/_source.json
C:/Users/YC1039/.workbuddy/binaries/python/versions/3.13.12/python.exe tools/fetch_tdoc.py
#   期望输出：=== _source.json 已生成，共 N 条 ===

# ② 判断是否有实质变化（忽略时间戳，只比条目内容）
python -c "
import json,hashlib,subprocess
h=lambda x: hashlib.sha256(json.dumps(x,ensure_ascii=False,sort_keys=True).encode()).hexdigest()[:16]
new=json.load(open('data/_source.json',encoding='utf-8'))['items']
old=json.loads(subprocess.run(['git','show','HEAD:data/_source.json'],capture_output=True,text=True,encoding='utf-8').stdout)['items']
print('新:',len(new),h(new),'| 线上:',len(old),h(old))
print('有变化' if h(new)!=h(old) else '无实质变化（仅时间戳）')
"

# ③ 生成 info.json
"C:/Users/YC1039/.workbuddy/binaries/node/versions/22.22.2-2/node.exe" tools/gen-info.js

# ④ 提交 + 推送（带重试与脱敏，见 05-命令清单.md §4）
# ⑤ 验证线上（见 §3）
```

### 2.2 主动巡检型（每两周 / 手动补新平台）

对应项目技能 `peizhen-proactive-scan`（位于 `.workbuddy/skills/peizhen-proactive-scan/SKILL.md`）。

| 步骤 | 命令 / 动作 | 关键约束 |
|---|---|---|
| 1 搜索 | 2 轮 WebSearch：先广撒（`陪诊师 接单平台 2026`、`合肥 陪诊 招聘 平台`），再对候选逐个验证（名称 + `官网/入驻/收费/骗局`） | 至少 2 轮 |
| 2 去重 | `python tools/edit_source.py list` | **按名称相似度去重**，不只看 id |
| 3 筛选 | 三条硬标准，任一不满足就跳过 | ① 有可验证主体（官网/小程序/公司）② 无前置费用（入驻费/押金/培训费/会员费）③ 平台内透明结算 |
| 4 写入 | `python tools/edit_source.py add --id slug --name "名称" --category national\|local\|regional --region "地区" --background "…" --condition "…" --fee "…" --rating 1-5 --tag "…" --link "…" --note "…"` | 不确定就**跳过并说明**，绝不凭感觉加 |
| 5 同步 | `python tools/sync_tdoc.py`（先 `--dry-run` 校对） | 失败可跳过，不影响发布 |
| 6 生成 | `node tools/gen-info.js` | 校验条数增加 |
| 7 推送 | 见 `05-命令清单.md` §4 | 远端校验 |
| 8 汇报 | 中文说明：新增了谁、跳过了谁及原因、当前总数 | 必做，便于追溯 |

**评分标准（rating）**：
- `5` 合规透明、有官方/国标背书
- `4` 真实实体 + 加分项（零抽成、覆盖广、有保险）
- `3` 区域平台，需本地验证单量
- `2` 存疑　`1` 不推荐

### 2.3 计划重置型（按需）

计划数据存在访客浏览器 localStorage，服务端只能改「默认值」。完整重置要动三处：

```bash
# ① 改默认计划：编辑 assets/js/store.js 的 defaultPlan()
#    字段：id / title / start / end / goal / tasks[{id,text,due,status,doneDate}]

# ② 生成导入文件 plan-import.json（格式见下）
# ③ 更新可读文档 求职计划.md
# ④ 提交推送
```

`plan-import.json` 格式（**值必须是 JSON 字符串**，与 `Store.exportAll()` 输出一致）：

```json
{
  "wb_jobsearch_plans": "[{\"id\":\"p0910\",\"title\":\"…\",\"start\":\"2026-09-10\",\"end\":\"2026-11-09\",\"goal\":\"…\",\"tasks\":[{\"id\":\"t1\",\"text\":\"…\",\"due\":\"2026-09-11\",\"status\":\"todo\",\"doneDate\":null}]}]"
}
```

> **老访客不会自动更新**：浏览器已有 `seeded` 标记时，`bootstrap()` 会跳过写入。必须让他在 `plan.html` 点「导入」选 `plan-import.json`，或清除该站点的「网站数据」（仅清 HTTP 缓存无效）。

## 3. 部署验证（每次推送后必做）

GitHub Pages 约 40~60 秒生效。验证顺序：

```bash
# ① 远端与本地是否一致
TOKEN=$(tr -d '[:space:]' < tools/.gh_token)
git ls-remote "https://${TOKEN}@github.com/zhuxingshifu1992/hefei-job-help.git" main
git rev-parse HEAD
# 两个 SHA 应相同

# ② 等 45~60 秒后验证线上内容
curl -s "https://zhuxingshifu1992.github.io/hefei-job-help/data/info.json" \
  | python -c "import sys,json;d=json.load(sys.stdin);print('条数:',len(d['items']),'| updatedAt:',d.get('updatedAt'))"

# ③ 页面可达性
for p in index info plan; do
  printf "%s: " "$p"; curl -s -o /dev/null -w "%{http_code}\n" \
    "https://zhuxingshifu1992.github.io/hefei-job-help/$p.html"
done
```

> 验证 `store.js` 是否部署成功时，直接抓源码比对更可靠（WebFetch 抓不到 JS 渲染后的列表）：
> ```bash
> curl -s https://zhuxingshifu1992.github.io/hefei-job-help/assets/js/store.js | grep -o 'id: "p[0-9]*"'
> ```

## 5. 变更留痕

任何流程/约定变更，收尾时必须更新：

1. `memory/decisionLog.md` —— 追加一条「决定 N」，写清原因与被否决方案
2. `memory/activeContext.md` —— 追加一行「YYYY-MM-DD 简述」
3. `memory/.handoff.md` —— 重写为最新交接状态
4. `delivery/` 对应文档 —— 若涉及运维流程
