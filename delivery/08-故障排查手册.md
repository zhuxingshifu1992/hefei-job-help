> 全部条目来自本项目真实发生过的故障。每条按「现象 → 常见误判 → 根因 → 诊断 → 解法 → 预防」组织。

## 故障 1：腾讯文档拉取报 `ERROR:no_token`

**现象**
```
RuntimeError: tdoc_call 失败:
ERROR:no_token - 未检测到腾讯文档登录票据，请在 WorkBuddy 中打开并授权腾讯文档连接器后重试
```

**常见误判**
> 「连接器断了，去 WorkBuddy 重新授权腾讯文档。」

**这通常解决不了问题。** 连接器状态显示 connected 时也可能报这个错。

**根因**
腾讯文档插件升级后换了版本目录，而脚本里**硬编码了旧版本路径**。新旧版本拼接取票地址的方式不同：

| 版本 | 拼出的 URL | 结果 |
|---|---|---|
| 旧（1.0.0） | `http://127.0.0.1:PORT/internal/tencent-docs/tokens` | **404** |
| 新（5.5.4） | `http://127.0.0.1:PORT/mcp/internal/tencent-docs/tokens` | 200 |

旧版少了 `/mcp` 段 → connector-proxy 返回 404 → 取不到票据 → 报 `no_token`。

**诊断（关键一步）**
```bash
cd /d/帮老弟找工作项目
TDOC_DEBUG=1 python "C:/Users/YC1039/.workbuddy/plugins/cache/workbuddy-builtin/tencent-docs-plugin/1.0.0/skills/tencent-docs/tencentdocs.py" \
  tdoc_call sheet-mcp get_cell_data '{"file_id":"ZLPnsrYSgVgU","sheet_id":"BB08J2","start_row":0,"start_col":0,"end_row":2,"end_col":11,"return_csv":true}' 2>&1 | head -5
```
看输出里的 `request ... tokens` 与实际报错：
```
[TencentDocsPluginToken] request connector-proxy token provider: http://127.0.0.1:63033/internal/tencent-docs/tokens
[TencentDocsPluginToken] connector-proxy token provider request failed: HTTP Error 404: Not Found
```
出现 `404` 即确认是路径拼接问题，**不是授权问题**。

**解法**
把脚本改为**自动发现最高版本插件目录**（不要只把 1.0.0 改成 5.5.4，下次升级还会断）：

```python
def resolve_skill_dir():
    env = os.environ.get("TDOC_SKILL_DIR")
    if env and os.path.isfile(os.path.join(env, "tencentdocs.py")):
        return env
    cands = []
    for d in glob.glob(os.path.join(PLUGIN_ROOT, "*")):
        p = os.path.join(d, "skills", "tencent-docs", "tencentdocs.py")
        if os.path.isfile(p):
            m = re.match(r"(\d+)\.(\d+)\.(\d+)", os.path.basename(d))
            cands.append((tuple(map(int, m.groups())) if m else (0,0,0), os.path.dirname(p)))
    if not cands:
        raise RuntimeError("未找到腾讯文档插件 tencentdocs.py")
    cands.sort(reverse=True)
    return cands[0][1]
```

本项目 `tools/fetch_tdoc.py` 已内置此函数，`tools/sync_tdoc.py` 通过 `from fetch_tdoc import resolve_skill_dir` 复用。

**预防**
- 任何脚本都**不要硬编码插件版本目录**
- 新增脚本时复用 `resolve_skill_dir()`
- 看到 `no_token` 先开 `TDOC_DEBUG=1` 看真实错误，不要直接去重新授权

## 故障 2：`node: No such file or directory`

**现象**
```
/usr/bin/bash: C:/Users/YC1039/.workbuddy/binaries/node/versions/22.22.2/node.exe: No such file or directory
```

**根因**
Node 版本目录名带后缀，实际是 `22.22.2-2`，不是 `22.22.2`。历史文档/自动化配置里写的是旧路径。

**诊断**
```bash
ls -d "C:/Users/YC1039/.workbuddy/binaries/node/versions/"*/
```

**解法**
```bash
"C:/Users/YC1039/.workbuddy/binaries/node/versions/22.22.2-2/node.exe" tools/gen-info.js
```

**预防**
- 用前先 `ls` 确认目录名
- 若某份 skill / 自动化里写死了旧路径，**顺手改掉**（本项目已修正 `peizhen-proactive-scan/SKILL.md`）

## 故障 3：git push 静默失败 / 超时

**现象**
- 命令没有输出，或直接超时
- `RESULT=0`，三次重试都失败

**根因**
agent 沙箱拦截网络访问。

**解法**
1. 执行推送命令时**绕过沙箱**
2. 用带重试的循环（见 `05-命令清单.md` §4）
3. 错误日志写到 Windows Temp，不要写 `/tmp`

**注意**：本项目实测推送常在**第 2~3 次才成功**，这是正常现象，不要误判为 token 失效。

## 故障 4：`/tmp/xxx: No such file or directory`

**现象**
curl 返回 200，但 `-o /tmp/xxx.json` 之后文件不存在，后续 grep/python 报错。

**根因**
本机 `/tmp` 在部分执行环境下不可写（尤其绕过沙箱时）。

**解法**：用管道，不落临时文件
```bash
curl -s "https://.../data/info.json" | python -c "import sys,json;d=json.load(sys.stdin);print(len(d['items']))"
```
或写到 `C:/Users/YC1039/AppData/Local/Temp/`。

## 故障 5：`git ls-remote` 返回空，误判为未推送成功

**现象**
```
REMOTE_MAIN=
LOCAL_HEAD =66ffe088...
MISMATCH
```
但明明刚 `PUSH_OK`。

**根因**
`ls-remote` 偶发网络抖动返回空；若命令里带 `2>/dev/null`，错误被吞掉，看起来就像「远端没有」。

**诊断**：去掉 `2>/dev/null` 重跑
```bash
git ls-remote "https://${TOKEN}@github.com/..." main 2>&1 | head -3
```

**解法**：多跑一次即可，或用 `git fetch` 后比对 `FETCH_HEAD`。**不要因此重复推送**。

## 故障 6：GitHub Pages 没更新

**现象**
推送成功、远端 SHA 一致，但线上还是旧内容。

**排查顺序**
```bash
# ① 是否等够时间（Pages 需 40~60 秒）
sleep 50

# ② 直接抓数据文件看时间戳
curl -s "https://zhuxingshifu1992.github.io/hefei-job-help/data/info.json" \
  | python -c "import sys,json;print(json.load(sys.stdin)['updatedAt'])"

# ③ 抓 JS 源码确认是否已部署（比抓渲染结果可靠）
curl -s https://zhuxingshifu1992.github.io/hefei-job-help/assets/js/store.js | grep -oE 'id: "p[0-9]+"'
```

**坑**：WebFetch / 无头抓取**拿不到 JS 渲染后的列表**，会误报「页面是空的」。判断部署是否生效，请抓**源码或数据文件**，不要抓渲染结果。

**其他可能**：浏览器缓存 → 强刷（Ctrl+F5）或用无痕窗口。

## 故障 7：计划页没变成新版

**现象**
推了新计划（`store.js` 的 `defaultPlan()` 已改），但打开还是旧计划。

**根因**
计划数据存在**浏览器 localStorage**，且只在首次访问时写入一次（`seeded` 标记）：
```js
function bootstrap() {
  if (localStorage.getItem(NS + "seeded")) return;  // 已有标记 → 不再写入
  save("plans", [defaultPlan()]);
  save("seeded", "1");
}
```
改服务端代码**改不动访客浏览器里已有的数据**。

**解法（二选一）**
1. 在 `plan.html` 点「导入」→ 选 `plan-import.json`（推荐，一击覆盖）
2. 清除该站点的**「网站数据 / Cookie 和网站数据」**后重开

**⚠️ 关键区分**：只清「缓存的图片和文件（HTTP 缓存）」**无效**——那只会重新下载 JS，localStorage 里的旧计划还在。必须清「网站数据」。

最省事的办法：**用无痕/隐私窗口打开**，一定是新版。

## 故障 8：差点把 token 提交上去

**现象**
`git status` 里出现 `tools/.gh_token`。

**根因**
`.gitignore` 没生效（文件先于忽略规则被 add 过），或用了 `git add -A`。

**立即处置**
```bash
git restore --staged tools/.gh_token        # 移出暂存区（保留文件）
git status --porcelain | grep gh_token || echo "已移出"
```
若**已经推送到远端**：立刻到 GitHub 吊销该 token（删文件没用，历史可检出），再重新签发。

**预防**
- 每次提交前跑：`git status --porcelain | grep -i gh_token && echo "⚠️" || echo "✅"`
- 慎用 `git add -A`（`tools/push.bat` 内部就是 `git add -A`，只想提交部分文件时请走手动流程）

## 故障 9：Windows 下的 LF/CRLF 警告

**现象**
```
warning: in the working copy of 'data/info.json', LF will be replaced by CRLF the next time Git touches it
```

**说明**：**无害警告**，不影响功能。

**想消除**
```bash
git config core.autocrlf input
```
并加 `.editorconfig`（见 `06-配置模板与脚本/.editorconfig`）。

## 故障 10：腾讯文档表格为空

**现象**
```
RuntimeError: 表格为空，请确认表格链接/权限
```

**排查**
```bash
grep -n "FILE_ID\|SHEET_ID" tools/fetch_tdoc.py
# 期望：FILE_ID = "ZLPnsrYSgVgU" / SHEET_ID = "BB08J2"
```
- 确认腾讯文档连接器处于 connected
- 确认该文档/子表没有被删除或改名
- 用 `TDOC_DEBUG=1` 重跑看原始响应

## 通用排错三步法

1. **先确认是不是网络/沙箱问题**：把命令单独重跑一次；网络命令绕过沙箱
2. **打开 debug 看真实错误**：腾讯文档用 `TDOC_DEBUG=1`；git 去掉 `2>/dev/null`
3. **区分「现象」和「根因」**：`no_token` 是现象，根因可能是 URL 拼错；「页面空」是现象，根因可能是抓取方式不对
