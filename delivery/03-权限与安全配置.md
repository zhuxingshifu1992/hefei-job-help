# 03 · 权限与安全配置

> 本项目最高风险点只有一个：**GitHub token 泄露**。所有规范围绕它设计。

---

## 1. GitHub Token（PAT）配置

### 1.1 为什么用 PAT 而不是密码 / gh CLI

- GitHub 已不支持用账户密码推 HTTPS
- **本机 `gh` CLI 不可用**（实测 `which gh` 无结果），因此不能用 `gh auth login`
- 结论：采用 **Fine-grained PAT + HTTPS URL 内联 token** 的方式推送，推完立刻把 remote 改回干净地址

### 1.2 创建 PAT（GUI，需人工操作）

路径：**GitHub 右上角头像 → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**

| 配置项 | 填什么 |
|---|---|
| Token name | `hefei-job-help-pages`（便于识别） |
| Expiration | 建议 **90 天**或自定义，到期前需轮换 |
| Repository access | **Only select repositories** → 选 `zhuxingshifu1992/hefei-job-help` |
| Permissions → Contents | **Read and write**（只需这一个，够推送代码） |
| Permissions → Pages | 无需（分支部署不需要额外权限） |

生成后**立刻复制**（关闭页面后不再显示）。

### 1.3 存放位置（唯一允许的位置）

```bash
# 写入 token 文件（单行，不能有换行/空格）
cd /d/帮老弟找工作项目
printf '%s' 'github_pat_xxxxxxxxxxxx' > tools/.gh_token

# 确认：应为 1 行、无尾随换行
wc -c tools/.gh_token
```

**规则**：
- 只放在 `tools/.gh_token`，**不要**写进任何 `.bat`、`.py`、`.md`、环境变量脚本
- 该文件必须被 `.gitignore` 忽略（见 §2）
- 读取时统一用 `TOKEN=$(tr -d '[:space:]' < tools/.gh_token)`，去掉可能混入的空白

### 1.4 使用方式（推完必须复位 remote）

```bash
cd /d/帮老弟找工作项目
TOKEN=$(tr -d '[:space:]' < tools/.gh_token)
[ -z "$TOKEN" ] && { echo "ERROR: token 为空"; exit 1; }

git push "https://${TOKEN}@github.com/zhuxingshifu1992/hefei-job-help.git" main

# ★ 无论成功失败，都要执行这一行，避免 token 留在 .git/config
git remote set-url origin https://github.com/zhuxingshifu1992/hefei-job-help.git
```

验证 remote 干净：

```bash
git remote -v
# 期望两行都是 https://github.com/zhuxingshifu1992/hefei-job-help.git（不含 token）
```

### 1.5 错误日志必须脱敏

推送失败时日志里会带 token，打印前务必替换：

```bash
LOG="/c/Users/YC1039/AppData/Local/Temp/push_err.log"
git push "$URL" main 2>"$LOG" || python - "$LOG" <<'PY'
import sys
tok = open("tools/.gh_token", encoding="utf-8").read().strip()
txt = open(sys.argv[1], encoding="utf-8", errors="replace").read()
print(txt.replace(tok, "***REDACTED***")[-800:])
PY
```

## 2. .gitignore（必须项）

当前内容（**完整保留，复刻时照抄**）：

```gitignore
.workbuddy/
tools/.gh_token
```

| 忽略对象 | 原因 |
|---|---|
| `.workbuddy/` | agent 记忆、技能、自动化配置，含会话上下文，不入库 |
| `tools/.gh_token` | **密钥**，一旦入库即泄露，且 Git 历史难以彻底清除 |

模板文件：`06-配置模板与脚本/.gitignore.template`

**新增密钥类文件时的动作**：先在 `.gitignore` 加一行，再创建该文件。顺序反了就可能被提交。

### 2.1 万一 token 已经入库了怎么办

1. **立刻到 GitHub 吊销该 token**（Settings → Developer settings → Revoke）——这是唯一有效的止损手段
2. 从工作区删除并忽略：`git rm --cached tools/.gh_token && echo "tools/.gh_token" >> .gitignore`
3. 注意：历史提交里的 token 仍可被检出，**必须吊销**，删文件不能解决问题
4. 重新签发生成新 token

## 3. 安全审计（定期执行）

### 3.1 检查工作区是否有密钥将被提交

```bash
cd /d/帮老弟找工作项目
git status --porcelain | grep -iE "gh_token|token|secret|\.env" \
  && echo "⚠️ 发现疑似密钥文件待提交" || echo "✅ 无密钥文件待提交"
```

### 3.2 检查已跟踪文件里是否含密钥

```bash
git grep -nIE "github_pat_[A-Za-z0-9_]+|ghp_[A-Za-z0-9]+" -- . \
  && echo "⚠️ 仓库内含疑似 token" || echo "✅ 仓库内未发现 token"
```

### 3.3 确认脚本中没有硬编码 token

```bash
grep -rn "github_pat_\|ghp_" tools/*.py tools/*.bat tools/*.js 2>/dev/null \
  && echo "⚠️ 脚本内硬编码了 token" || echo "✅ 脚本内无硬编码 token"
```

> 本项目已审计：`push.bat` 从 `tools/.gh_token` 读 token，`publish.bat` 以参数接收，均**无硬编码**，且 `push.bat` 推完会复位 remote。

## 4. 仓库访问权限

| 角色 | 权限 | 说明 |
|---|---|---|
| 本人（zhuxingshifu1992） | Owner | 唯一维护者 |
| 访客（含弟弟） | 只读（Public 仓库天然可读） | **不能**给他写权限，他没有 GitHub 操作需求 |

**无需配置协作者**。若将来要多人维护：Settings → Collaborators → Add people，权限给 `Write` 即可，并给对方单独签发 token。

## 5. 数据与隐私

- 仓库是 **Public**，因此 `data/_source.json` 中的平台信息被视为**公开信息**
- 曾出现过的敏感内容：本地公司招聘联系人手机号（如妙小医杨经理电话）。**入库前确认此类信息是否适合公开**；如不适合，应放在不入库的本地文档里
- 计划数据（完成进度）只存在访客浏览器，**不上传服务器**，天然无隐私风险

## 6. 沙箱与网络（本机特有）

推送、抓取线上内容属于网络操作，在 agent 沙箱下会被拦截。表现为命令无输出或超时。

**处理**：执行网络命令时绕过沙箱（在工具调用中关闭沙箱），并且：

- 输出重定向到文件时，优先写到 Windows Temp（`C:/Users/YC1039/AppData/Local/Temp/`），`/tmp` 在本机偶发不可写
- 网络命令要带重试（见 `06-配置模板与脚本/` 中的一键脚本）
